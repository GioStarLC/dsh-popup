# 设计与实现

README 只讲怎么用。这里记的是为什么这样做，以及在 DSH 里怎么落地。

## 入口按投入分级

阅读并逐条回应几段文字不是一个动作，中间隔着：选中、写下看法、继续读。所以输入框不是写答案的地方，只是最后交付的出口。

| 阶段 | 信号 | 代价 | 允许做什么 |
| --- | --- | --- | --- |
| 注意 | 结束选区的 mouseup | 无 | 画一个 32px 按钮 |
| 打开 | 指针停留 160ms，或点击 | 一次移动 | 画卡片并接管光标 |
| 提交 | 输入，或点一个答案 | 一句话 | 存储、上色 |

第一级刻意不设防：拖选也会让按钮出现。闸门防的是上面几项，也就是光标、高亮和已存的注，所以一次误拖最多让屏幕上多一个圆，4 秒后自己消失。

入口只对最新一条助手回复开放：草稿回答的是那一条，旧轮次的文字不该在这里被引用；已经存在的旧标记只留在页面上，交付时同样排除。

## 几个取舍

**按钮可以介绍自己，但不追着人跑。** 出现时轻弹一下，外圈光环扩一次就停，260ms 的位移全部落在按钮自己的面积里。更早的版本只做 90ms 淡入，安静，但容易被完全错过；现在这一点动效只发生在“刚选中”的一瞬间，不滑向正文，也不循环。

**按钮不等。** 早期版本先把按钮压后 90ms，又压到 220ms，都不对：手势结束后才出现的控件看起来像残留物。它不抢焦点、不画东西、会自己走，早出现比晚出现便宜。

**不用文字按钮。** 最初在选区旁画 11px 的「批注」，在正文上读起来像渲染瑕疵，也不像能按的东西。现在用 32px 圆加 18px 气泡：先于文字表达“可以按”，动词放进 `aria-label` / `title`。32px 是能稳定点中的下限，再大就会变成压在正文上的面板。

**卡片只有一层。** 早期要先开卡片，再点「引用并附注」才看到答案；第二层只是因为卡片放不下输入框。合成一层后，任何回答都只要一个动作。

**标记不是引用。** 标记表示“我注意到了”，不进消息；引用表示“这是我回答的一部分”。全部交出去等于替读者说话，所以只有引用会写进输入框，按钮上的计数也只统计还没交付的引用。

## 标记如何挺过虚拟化

对话是虚拟化且增量组装的：屏幕外的 flow item 会卸载，旧轮次按需生成，流式回答持续重渲染。所以保存的 DOM `Range` 不能当标记，标记也不能是 DOM 节点。标记存成锚点：

| 字段 | 含义 |
| --- | --- |
| `key` | 所在 flow item 的 `data-chat-anchor-key`，由 `stepKey(turn, step)` 得出，跨刷新、重启、翻页、切换会话都稳定 |
| `quote` | 选中的文字 |
| `prefix` / `suffix` | 两侧各约 24 个字符的上下文，用来挑出正确的那一处 |
| `index` | 锚点内的保留字符偏移，用作位置漂移的提示 |
| `sessionId` | 按会话归档，两个会话可以都有 `step:1` |
| `replyKey` | 标记所属助手回复的 `data-chat-node-key`。选中时写入，交付时与新回复比对；不属于本轮草稿的标记只上色、不交付 |

上色用 CSS Custom Highlight API：`CSS.highlights.set(name, new Highlight(...ranges))` 加一条 `::highlight()` 规则。不往对话里插节点；自定义高亮画在 `::selection` 下面，所以选中已标记的段落时，正常选区仍然可见。

Range 从不存储。每次重绘都走一遍带标记锚点的可见文本，找到引文，再按 prefix、suffix 和相对 `index` 的偏移给每个出现位置打分。两侧比较都忽略空白，因为 `selection.toString()` 会插入 DOM 遍历复现不了的块分隔符。歧义的引文会被拒绝，而不是猜。标错句子的注比暂时标不出来更糟。

## 占用的三个位置

| 位置 | 作用 |
| --- | --- |
| `shell.overlay` | 渲染弹窗和标记样式表。整帧浮动层，滚动容器和 transform 祖先都裁不到 |
| `conversation.input.dock` | 不渲染内容，只用来取当前会话的 input 接口（`input` + `inputActions`） |
| `conversation.input.left` | 画插入按钮和自动开关，位于输入框自己的工具行 |

交付走已发布的 `InputActions`：`captureInsertion()` 取区间，`insertText()` 写文字，草稿历史只多一步撤销，编辑器 DOM 不被碰。撤回是唯一一次重写草稿，用 `setDraft()` 从纯文本重建，且只在块逐字节完整、草稿没有引用 chip、输入框不在提交中、输入框属于标记所在会话时进行；其余情况宁可拒绝也不近似。

## 高亮颜色

标记颜色不用主题变量：主题没有暴露荧光笔颜色，自定义属性也无法可靠地继承进 highlight 伪元素。早期版本用半透明的 `var(--dsw-alias-brand-primary)`，画出来是平的灰色。所以 `::highlight()` 写死黄底深字：

```css
::highlight(dsh-select-consent-mark) {
  background-color: rgba(255, 212, 64, 0.8);
  color: #1b1b1b;
}
```

一条规则同时适配明暗主题，对比度约浅色 12.6:1、深色 8.5:1。

## 行为细节

- 追加是追加，从不替换：已有文字留在上面；草稿本身以换行结尾时，不会多加一个换行。
- 插入时加在内容前面的那个换行属于这批内容。撤回最后一块时，换行一起走，草稿回到原样。
- 块以空行结尾，光标落在其后，下一句从新的一行开始。
- 自动插入在输入框 `focusin` 之后一个任务执行：指针自己的光标定位发生在这之后，同步插入会把光标送回输入框顶部。
- 自动关闭时，进入空的输入框会脉冲按钮，并提示「有 N 条批注待填入」。提示每批只播报一次。
- `input`、`textarea` 以及输入框（composer）内的选区从不引用；打开着的弹窗里的选区忽略。
- 只有最新一条助手回复里的选区会出入口；更早轮次、侧边栏、文档预览里的选区不提供操作。旧轮次已有的标记仍会高亮，但交付时排除。
- 标记存在 `localStorage` 的 `dsh-select-consent/marks/v1`，每个会话最多 200 条，最多 40 个会话。
- 卡片在点击外部、`Escape`、滚动、窗口尺寸变化、选区收起时关闭；注输入框例外，它是一个小表单，内容在页面滚动时保留。
- 注输入框打开期间，插件在 `.dsh-composer-anchor` 上设 `aria-expanded="true"`，否则关闭输入框的那个 Enter 会同时把消息发出去。
- 标记所在的 flow item 不在了（压缩丢掉了这一轮），只是不上色，不会被删除。

## 一条引用的格式

```markdown
> 第一步：用 Redis
> 运维成本高
我的回答：这条我认同
```

`我的回答：` 不是装饰。块引用后面紧跟的普通行会被当成引用的一部分，没有这个标签，读者的话就会以模型自己的文字的身份送进下一轮。有了标签，注前面也不需要空行。

引文**内部**的空行保持引用（单独一个 `>`），多段引用不会散成两个块；块引用本身可以中断段落，所以即使它前面只有一个换行，也不会并进已经写好的内容。
