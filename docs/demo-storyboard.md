# 录屏分镜

一条无声演示：30 秒，硬字幕，一次讲完「选中 → 卡片 → 草稿」。
主片是 MP4；README 首屏放其中 10 秒的 GIF——30 秒版里「入口」和「卡片」正好相邻，一张就装得下。

## 成片规格

| 项 | 值 |
| --- | --- |
| 画面 | 1440×900 窗口录制，导出 1920×1200（16:10，跟随窗口）；要 16:9 就按下面的 pad 命令补边 |
| 帧率 | 60fps；动效（气泡轻弹、光环）在 30fps 下会糊 |
| 声音 | 无音轨，靠字幕 |
| 时长 | 主片 30 秒 |
| GIF | 一张：0:03–0:13（选中 → 卡片 → 同意），10 秒，800px，≤ 4.5MB |
| 归档 | `docs/media/` 是本地工作目录，**不进仓库**；README 引用的是 GitHub 附件 URL，见「发布演示」 |

## 录制前

1. 新开一个会话，问一句能产出 2–3 段可选中文字的回答（列表或分点最适合，选起来边界清楚）。
2. 确认输入框是空的，并且自动填入是开的（输入框工具行左侧的开关）。
3. 关掉通知和勿扰以外的弹窗；侧边栏里不想露出的会话标题先改掉。
4. 浏览器字号 `Cmd +` 一档，窗口宽度固定在 1440，别在录制中拖动窗口。
5. `Cmd + Shift + 5` → 录「所选窗口」→ 麦克风关。整条一次拍完，剪辑里再切；分镜只是切点。

## 分镜

时间从 0 开始计，已按成片剪掉等待后的长度。30 秒的预算下每段只够一个动作，
所以「发送后取消标记」和「手动填入 N」不进主片——前者适合单独再录一条，
后者要提前攒一条未交付的引用，30 秒里讲不清。

| # | 时间 | 画面与操作 | 字幕 | 剪辑备注 |
| --- | --- | --- | --- | --- |
| 1 | 0:00–0:03 | 对话停在助手回复上，指针从正文上划过 | 读到一半，想回一句。 | 开场不要 logo，直接进正文 |
| 2 | 0:03–0:08 | 选中最新回复里一句话 → 松开 → 气泡按钮弹出（轻弹 + 光环），**停 1.5 秒**，不点 | 选中就有入口。不抢焦点，4 秒后自己消失。 | 这 1.5 秒不要加速，动效是卖点；停完立刻切，别等它自己消失 |
| 3 | 0:08–0:13 | 指针回到按钮，悬停 → 卡片在落点打开 → 点 👍 同意 | 一张卡片回答完：同意、不同意、标记。 | 悬停的真实等待约 160ms，保留原速，别剪成 0 |
| 4 | 0:13–0:19 | 再选一段 → 卡片输入框打字「这条我认同，但第三步要改」→ Enter | 写了字也不会丢：答案在前，你的话在后。 | 打字段 2× 加速，压进 6 秒 |
| 5 | 0:19–0:23 | 再选一段 → 点「标记」→ 高亮留在原文上 | 标记 ≠ 引用，不进消息。 | 高亮出现后停 1 秒再切 |
| 6 | 0:23–0:28 | 点进空的输入框 → 草稿自动出现 `> 原文` + `我的回答：…` | 点进空的输入框，草稿已经写好。 | 用光标划过「我的回答：」这一行，说明标签不是装饰 |
| 7 | 0:28–0:30 | 空镜或仓库地址 | dsh-popup：无构建、无依赖、不联网。 | 可以叠在镜头 6 的尾巴上 |

## 字幕规范

- 单行 ≤ 16 字，最多两行；底部居中，距底 8%，深色半透明底 + 白字。
- 出现在操作**之前**约 200ms，跟着动作走，不要先讲后做。
- 术语只用这几个词，和 README 一致：批注、标记、引用、草稿、填入 N、我的回答：。
- 可用的 SRT 在 [`demo-subtitles.srt`](demo-subtitles.srt)，时间轴按上面的切点排好；改了切点就整体平移，别逐条改。

## 剪辑

要处理的等待只有三处：

| 位置 | 真实时长 | 处理 |
| --- | --- | --- |
| 悬停打开卡片 | 160ms | 原速 |
| 气泡按钮自消失 | 4 秒 | 不拍进成片，停 1.5 秒就切走 |
| 打字 | 视手速 | 2× |

导出主片（窗口是 16:10，缩到 1920×1200）：

```sh
mkdir -p docs/media
ffmpeg -i raw.mov -vf "scale=1920:-2,fps=60" -c:v libx264 -crf 20 -pix_fmt yuv420p -an docs/media/demo.mp4
```

要 16:9（B 站、YouTube），补黑边而不是裁画面：

```sh
ffmpeg -i raw.mov -vf "scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:-1:-1,fps=60" \
  -c:v libx264 -crf 20 -pix_fmt yuv420p -an docs/media/demo-16x9.mp4
```

剪 README 用的 GIF（30 秒版里镜头 2、3 相邻，一张就讲完「选中 → 卡片 → 同意」）：

```sh
# 入口 → 卡片 → 同意（0:03 起 10 秒）
ffmpeg -ss 3 -t 10 -i docs/media/demo.mp4 \
  -vf "fps=12,scale=800:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" \
  -loop 0 docs/media/demo.gif
```

想再加一张讲草稿的（0:23 起 5 秒，放功能列表旁边而不是首屏）：

```sh
ffmpeg -ss 23 -t 5 -i docs/media/demo.mp4 \
  -vf "fps=12,scale=800:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" \
  -loop 0 docs/media/draft.gif
```

体积先量再发：

```sh
ls -lh docs/media/demo.gif
```

这张片子的地板价是 4MB 左右，不是 1MB。实测同一段 10 秒素材：800px/12fps 是 4.75MB，800px/10fps 是 4.07MB，`gifsicle -O3 --lossy` 再省 6%——因为 ffmpeg 已经用透明帧做差分，没有多少冗余可挖。原因在内容不在编码：深色 UI 的文字抗锯齿和阴影几乎不给 LZW 留空间。

所以想让 gif 更小，只能减内容：

- `-t 8` 缩短，或降到 640px；
- 缩画面比降帧更伤：正文在 800px 下刚好清楚，缩到 640px 后 README 再放大回去就糊了；
- `tools/make-demo-gif.sh` 就走这条梯度（800px 从 24fps 退到 8fps，再退 640px），预算 4.5MB。

视频是另一个数量级：同样 10 秒，mp4 不到 1MB。gif 只做首屏那 10 秒，完整演示给链接。

## 发布演示

README 里不存 gif，只存它的 URL。发布流程：

1. 在仓库里开一个 issue（标题写 `demo asset`，别关），把 `docs/media/demo.gif` 拖进正文。
   GitHub 会把它传到 user-attachments，插入一条
   `https://github.com/user-attachments/assets/<uuid>`。
2. 复制那条 URL，替换 README 第 17 行的 `src`。
3. 正文里什么都不用写，issue 提交后保持打开——附件挂在 issue 上，关掉不一定失效，但别赌。

为什么不用 release 资产：那条链路按二进制下载走（`application/octet-stream`），README 的图片要经 GitHub 的 Camo 代理，类型不对就是碎图，而且是在别人浏览时才碎。附件走的是图片类型，稳，也不占 release 页面的语义。

为什么不用 Git LFS：LFS 免费额度 1GB/月流量，一个 6MB 的 gif 被看 170 次就烧光，流量超了 README 直接裂图。

字幕走剪辑软件，不要指望这台机器上的 ffmpeg：剪映 / DaVinci / Final Cut 都能直接导入
[`demo-subtitles.srt`](demo-subtitles.srt)，中文字体和描边在软件里调比滤镜省事。命令行烧字幕
需要带 libass 的 ffmpeg，本机的 `ffmpeg 8.1`（Homebrew）没有编进去：

```sh
ffmpeg -filters | grep subtitles        # 有输出才说明能用
ffmpeg -i demo.mp4 -vf "subtitles=demo-subtitles.srt" -c:v libx264 -crf 20 -pix_fmt yuv420p -an demo-subtitled.mp4
```

## 拍完自检

- [ ] 每个镜头的字幕和画面说的是同一件事，没有先讲后做。
- [ ] 镜头 6 里 `我的回答：` 标签清楚可见。
- [ ] 高亮是黄底深字，没有变成浏览器默认选区色。
- [ ] 画面里没有真实 API key、私人会话标题、桌面通知。
- [ ] 气泡按钮那 1.5 秒没被加速，也没被剪成「卡住不动」。
- [ ] `demo.gif` 不超过 4.5MB，看得出「选中 → 气泡 → 卡片 → 同意」四步。

## 拍不出来时先查这些

- 入口出现在**助手回复**的正文里（任意一轮）；选中用户消息、侧边栏、文档预览都不会有按钮，这是设计。
- 镜头 6 需要输入框为空；里面有字时它不会动你的草稿，只会脉冲按钮提示「有 N 条批注待填入」。
- 自动填入被关掉时，进空输入框草稿不会自己出现。
- 插件刚装完要刷新窗口，否则客户端 bundle 还没进启动图。
